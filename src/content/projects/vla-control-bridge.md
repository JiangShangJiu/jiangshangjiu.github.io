## 要解决的问题

VLA 策略以低频输出动作块（action chunk），而低层控制环以高得多的频率运行。
中间这一层要同时处理：块内插值与时间重参数化、关节限位与速度 / 加速度约束、
块边界处的连续性、推理延迟与到达抖动，以及对越界动作的拒绝或降级。

多数开源栈把这层逻辑散落在 demo 脚本里，与具体模型、具体机器人耦合，
**没法单独测试**——策略换了、延迟变了，执行层行为是否仍然安全，只能靠跑整套系统碰运气。
我在第一份工作做 VLA 真机验证时，相当一部分问题最终定位在这一层而不是模型本身。

这个模块把桥接层隔离成独立被测对象：策略侧用**确定性替身**（录制的动作序列、
脚本化策略）驱动，不依赖 GPU 推理，就能对执行层做系统性的故障注入评测。
这也意味着本模块**不评价任何 VLA 模型的任务成功率**——那是策略的属性，不是执行层的。

## 方法

```text
策略替身（录制序列 / 脚本化策略，可注入故障）
            ↓
动作块校验（限位、速度 / 加速度、工作空间包络）
            ↓
插值与在线重参数化（块内平滑 + 块边界连续）
            ↓
安全包络监督（越界 → 降级 / 平滑停止）
            ↓
高频控制环执行（MuJoCo 闭环）→ 全量日志
```

1. **策略替身是第一公民**。回放录制序列保证逐次确定；脚本化策略按需生成
   边界用例（越限动作、块间跳变、乱序到达），每个用例有预期的桥接层行为。
2. **校验在插值之前**。动作块先过限位 / 速度 / 加速度 / 工作空间检查，
   不合法的块按策略降级（截断、缩放或拒绝并保持安全轨迹），决策记入日志。
3. **块边界连续性是硬约束**。上一块执行中途收到新块时，从当前运动状态
   （位置、速度、加速度）做在线重参数化衔接，不允许向控制环下发不连续指令。
4. **故障注入是评测的主轴**。延迟抖动、块丢失、块间不连续、持续越限动作
   逐项注入，考察桥接层是否始终维持约束与连续性。

动力学模型复用[动力学建模与参数辨识](/projects/robot-model/)项目的产出，本模块不重做辨识。

## 指标与验收口径

首批「无护栏 vs 有护栏」对照已跑完，数字来自仓库 `artifacts/summary.md`。
本模块仍然**不报告 VLA 任务成功率**，只报告执行层在故障注入下的包络与代价：

| 指标 | 口径 | 首批结果 |
| --- | --- | --- |
| 最大侧向偏差 | 相对参考路径的最大横向偏离 | 无护栏约 **153 mm** → 有护栏约 **25 mm** |
| 峰值速度 | 下发到控制环的末端 / 指令速度峰值 | 无护栏 **1.69 m/s** → 有护栏 **0.78 m/s** |
| 进度债 | 护栏截断 / 降速相对原动作块进度的时间滞后上界 | 最长 **2.75 s** |
| 护栏行为 | 越界块是否被截断、降速或拒绝并保持安全轨迹 | 有护栏侧偏差与速度均被压住，代价体现为进度债 |

也就是说：关掉安全包络时，替身输出可以把机器人甩到约分米级侧偏、近 1.7 m/s 峰值；
打开护栏后侧偏压到约 2.5 cm、峰值速度约减半，同时最多欠下约 2.75 s 的进度。
约束违例计数、块边界加速度分布等细项会随后续评测报告继续补表，不改这组对照数字。

## 失败案例与失败边界

评测按用例组织，每个故障注入用例要么验证桥接层按预期处置，要么成为失败案例
（配置 + 日志 + 复现命令）留档。同时明确**本模块不覆盖**的范围：

- **策略分布**：替身的动作统计不等于真实 VLA 的输出分布，
  只能覆盖设计出的边界用例，不能证明对任意策略输出安全；
- **感知误差**：替身直接给动作，视觉 / 语言侧的误差传播不在被测链路内；
- **执行器模型**：MuJoCo 的理想执行器不含电流环动态与力矩饱和的真实形状，
  延迟注入是设定模型而非实测。

## 向实机扩展

桥接层对上（策略）与对下（控制环）各是一个窄接口：上游把替身换成真实模型的
推理进程，下游把 MuJoCo 执行换成实机驱动，校验、插值与安全包络逻辑原样保留。
故障注入用例库在实机联调前先在仿真里过一遍，是这层模块对真机部署的主要价值。

```bash
pip install -e ".[dev]"
armlab-vla-bridge
```
